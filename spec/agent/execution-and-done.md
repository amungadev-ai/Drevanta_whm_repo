# Full-platform execution and acceptance

The owner directed delivery across Server & Platform Administration, Hosting Provider/Reseller/Agency, Website Owner and Developer. Build waves set dependency order. Every source-required behavior remains in the final certification backlog. Optional or conflicting scope is carried forward for explicit classification. A wave can close its own verification and still leave the platform release blocked.

## Future agent protocol

Consume the graph and select a ready node only after its prerequisites, applicable decision records and exact contract/fixture revisions are frozen. Record work item, cap/requirement IDs, branch, base commit, permitted targets/verbs, intended tests, evidence destination and rollback. Fetch short-lived scoped credentials only through authorized custody. Use a task branch, reviewed PR and required CI; protected merges and deployment require recorded independent authorization. A prior approval binds exact role, repo, target, verb, artifact and window. Never infer authority from network reachability. A blocked node emits an exception with failing predicate, owner, evidence and safely independent nodes. Continue eligible independent work without routine prompts. Stop affected work on ambiguous ownership, credential exposure, unsafe recovery, contract conflict or expired authority.

## Full-platform Definition of Done

1. Scope ledger has dispositions for every source obligation, capability and recorded/observed UI control. Required scope has no exclusions. Optional and conflicting items have explicit owner-approved scope before release certification. A deferred build wave is not a scope exclusion.
2. Every required action has a frozen request, response, error, owner/grant, persistent transition, allowed host/provider effect, UI state when applicable, audit, denial, retry and recovery contract. Tests bind exact fixture and build. Every applicable test passes. N/A requires signed exact-scope reason.
3. Module and cross-module verification includes delegated Provider → Reseller → Website and Developer linked deployment, worker crash reconciliation, tenant denial, installation and upgrade, preview and rollback, support access expiry, and full loss-of-host restore. Each requires an immutable artifact and independent observed postconditions.
4. CI verifies dependency lock, lint/types, contract and migration compatibility, secret redaction, static authorization, isolated integration, browser/accessibility, candidate provenance, signature and dependency inventory. Bind evidence to the exact reviewed commit and digest; promote the same artifact.
5. Authorized disposable VPS matrix covers clean/repeat/interrupted install, unprivileged processes, denied helper caller, supported profile, protected services, firewall/SSH rollback with independent connection, restart/reboot convergence, and install/upgrade recovery. Collect snapshots and correlation IDs; test environment only.
6. Restore encrypted off-host backup into an isolated replacement target with independent key recovery. Compare manifest, application data, integrity and readiness; capture policy-defined RPO/RTO measurement. Rehearse rollback bound to prior known-good digest/config and compatible schema. If incompatible, use isolated restore and reviewed cutover. Observe signal thresholds and record unknown outcomes separately.
7. Production certification requires whole-scope traceability, exact artifacts, all required completed waves, zero unresolved applicable critical/high blockers, approved compatibility and thresholds, staged recovery and rollback evidence, human release approval with target and window, and operational ownership. No stage receives passing credit for an unexecuted case.

Published gates use PASS, FAIL, BLOCKED, NOT_RUN and reviewed N/A. Documentation verification is a distinct gate. An agent can freeze only choices that are explicitly authorized or proven by approved source; it cannot convert a recommended default into approval.
