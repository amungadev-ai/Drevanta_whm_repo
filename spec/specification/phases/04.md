# Phase 04 — Data architecture and persistence

**Owner role**  Data lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Use opaque IDs, UTC timestamps and monotonically increasing resource generations. Ownership edges, membership changes, quota reservations and jobs need transactional integrity. Persist audit/outbox metadata alongside mutations. Engine and migration tool remain open. Separate platform persistence from customer database provisioning. Restrict secret material to encrypted storage via secret references.

## Contract and operational behavior

Logical records: installation → host; organization → hosting account → website; project → environment → deployment → artifact; membership links principal and scope; resource links owner, host and desired/observed generations. Operations link actor and resource, while attempts link operation and fence. Unique constraints cover tenant natural keys, global normalized hostname when applicable, idempotency namespaces and active deployment target. Audit and outbox records are append-only. Secret refs contain key identifier/version and no plaintext. Test forward migration against populated prior versions, restore incompatibility and interrupted migration.

## Acceptance and test design

**REQ-P04-01 / AC-P04-01**. Cross-scope foreign references are rejected transactionally. Competing updates to one generation allow exactly one commit and no detached rows. Backup schema, data and encryption metadata before incompatible migrations.

**TC-P04-01 · Procedure**. Run two writes with generation 7 against one resource and attach a membership from an unrelated organization.

**Expected**. One write commits generation 8, the other returns 412. Invalid membership produces no side effects.

**TC-P04-02 · Companion test**. Migrate a populated previous snapshot and verify known foreign keys, rows and audit sequence.

**Expected**. All seeded owners and references survive and the schema revision advances once.
