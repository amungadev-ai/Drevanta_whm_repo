# Phase 02 — Product requirements and architectural principles

**Owner role**  Product lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

The unified Server & Platform Administration console is an approved product direction (P1 OD-01 and ADR-020). The self-hosted Linux control panel has four persona workspace views over shared resources. Model operator tasks around observing, planning, applying and verifying. Distinguish an installation owner, resource owner, delegated operator and customer. Start with core safety and usability, then enable hosting and application slices only through approved scope. Ship no feature action for a module whose adapter or scope is unavailable.

## Contract and operational behavior

Prioritize install → claim → sign in → scoped read → safe mutation → verification as the first end-to-end slice. Next candidate slices are managed websites and delegated hosting, then artifact-based development. Approval record fields are feature ID, scope by phase/release, deployment target tier, owner, dependencies, exclusions, signed decision, and date. Tenant safety, recovery, accessibility and observable operations are mandatory quality attributes for an enabled slice. Optional modules require detection of installed, supported, configured, and permitted states.

## Acceptance and test design

**REQ-P02-01 / AC-P02-01**. Every enabled capability must have a release commitment, accountable owner, eligible scope, and dependency list. Unsupported actions return capability_unavailable with a reason and never enqueue work.

**TC-P02-01 · Procedure**. Enable a feature flag for a module with no readiness proof. Try its action from UI and API.

**Expected**. UI explains unavailability. API returns 409 capability_unavailable. Job count is zero.

**TC-P02-02 · Companion test**. Approve a seeded capability with an eligible adapter and view it from the assigned persona.

**Expected**. Capability is available only in its approved scope and reports its dependency status.

## Definition of Done

- **Documentation**. Source and dependent contracts are linked, the interface and tests are reviewable, and blockers have explicit decisions and owners. Review any open exceptions before semantic sign-off.

- **Engineering**. The capability behaviors test against the exact authorized build and environment. Evidence covers TC-P02-01, TC-P02-02 and every applicable capability test. Data, policy, recovery and audit expectations hold.
