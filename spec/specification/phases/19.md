**Owner role**  Design and UX lead

## Purpose and scope

Server Admin sees host/global health and authorized infrastructure actions. Hosting sees organizations, accounts, quotas and delegated customer operations. Website Owner sees site lifecycle, access, domain, files, runtime and backups. Developer sees project, build, deploy, environments, release and secrets. Keep context visible in breadcrumbs and dangerous confirmations, follow prototype settings-hub navigation, and support keyboard operation and status announcements.

## Contract and operational behavior

Server entry server-admin.html; Hosting index.html; Website website-owner.html; Developer developer.html. Login and onboarding have distinct flows. Standard surface shows current workspace/scope, purpose, actions, status freshness and operation references. Test empty/loading/partial/stale, revoked grant, unavailable capability and operation failure, with keyboard traversal and focus restoration. Preserve the source design palette and settings breadcrumbs as design evidence. Stale requests are keyed to active selection revision.

## Acceptance and test design

**REQ-P19-01 / AC-P19-01**. Switching context clears previous sensitive content and loads only server-authorized target data. All enabled actions have pending, denied, validation failure, timeout/retry and success UI states with correlation reference.

**TC-P19-01 · Procedure**. Keyboard-switch from Site A to Site B while A detail request is delayed. Follow settings breadcrumbs, trigger a failed scoped operation, then use back navigation.

**Expected**. Late A response is discarded. Context remains B. Focus and status are announced and no A content reappears.

**TC-P19-02 · Companion test**. Traverse each primary workspace and supported settings path by keyboard.

**Expected**. Context, focus, labels and status are visible and consistent with authorized selection.
