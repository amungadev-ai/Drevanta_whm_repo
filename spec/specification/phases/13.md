# Phase 13 — Databases, storage and file services

**Owner role**  Data services lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Use per-resource database principals and scoped SFTP identities. Treat filenames, symlinks, editor content and archive members as hostile. Resolve operations relative to verified directory handles, avoid symlink traversal and use atomic writes. Reserve quotas for streams and expanded archives. Separate secret creation and delivery from ordinary database metadata. Revoke before asynchronous cleanup.

## Contract and operational behavior

Use per-site stable file root, scoped open/edit/move/delete semantics, expected generation for overwrites and an explicit conflict response. Quarantine uploads prior to validate/activate. Archive tests cover decompression limits, nested traversal, symlink and hard-link entries. SQL provider capabilities include provision, health, rotate, export and drop, with engine-specific isolation tests. Storage inspection cannot imply filesystem mutation permission. Keep data export access separate from secret delivery and global disk administration.

## Acceptance and test design

**REQ-P13-01 / AC-P13-01**. Reject path escapes, absolute archive members, symlink races and oversized decompression before any out-of-root write. DB credentials can act only on the assigned database.

**TC-P13-01 · Procedure**. Swap an upload directory for a symlink between preflight and write. Try cross-database SQL from the site's principal.

**Expected**. No outside writes and no foreign database data or mutation. Temporary reservations/files are released.

**TC-P13-02 · Companion test**. Upload, edit with current version, and provision an isolated SQL database for the same site.

**Expected**. Stored bytes match expected digest and own database CRUD succeeds.

## v2.0 audit correction

**AUD-13 · Critical.** DB metadata visibility, data-plane isolation, archive safety and credential lifecycle were compressed into one check.

Separate CRUD permission from DB grant and rotation. Respect data-engine limits. Hard links, symlinks and mount identity are separate threat scenarios; destructive DB drops need review/retention rules.
