# Phase 08 — Server lifecycle, OS compatibility and updates

**Owner role**  Host engineering lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Record host identity, OS release, architecture, init, package adapter, firewall adapter and storage/network characteristics. Inventory read-only if incompatible. Protect OS packages and platform units. Preflight changes for repository integrity, package lock, free space, backup and access. Stage updates in maintenance windows. Mark host degraded if post-reboot checks fail and collect a redacted diagnostics bundle.

## Contract and operational behavior

Compatibility tuple fields: distribution, release, architecture, kernel/init, package backend, firewall adapter, filesystem, runtime packages, test image digest and support status. PRD Ubuntu/Debian apt/dpkg is a candidate. Support tiers must include fresh install, upgrade from supported prior versions and restore. Separate panel update from OS updates. If rollback cannot safely undo a package migration, restore using approved recovery plan. Log discovered and desired versions, disk pressure, reboot requirement and postboot access/health.

## Acceptance and test design

**REQ-P08-01 / AC-P08-01**. Unsupported tuples and failed preflight cause zero package changes. An accepted reboot drains work and resumes verification with the same operation ID, fencing competing mutations.

**TC-P08-01 · Procedure**. Mock an unsupported init and a package lock, then reboot a supported host mid-update.

**Expected**. Both unsafe attempts produce no package effects. Supported operation resumes without starting a second transaction.

**TC-P08-02 · Companion test**. Upgrade an eligible host and confirm independent access and service health after reboot.

**Expected**. Host shows new approved version, stable host identity and healthy result.
