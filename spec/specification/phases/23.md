**Owner role**  API lead

## Purpose and scope

Use versioned JSON, opaque resource IDs and scoped cursor pagination. Mutations validate typed inputs, auth, generation and idempotency. Define stable errors, audit correlation and explicit compatibility windows. Adapter manifests declare version, operations, permissions, dependencies and resources. Reject incompatible or unsigned modules under approved policy. Verify inbound signatures over raw bytes before deduplication or effects.

## Contract and operational behavior

Candidate API prefix /api/v1. JSON errors carry code, correlation_id and safe detail. 401 unauthenticated, 403 denied in visible scope, 404 nonexistent or hidden target, 409 conflict/unavailable, 412 stale generation, 422 invalid input. 202 returns operation_id and status link for asynchronous mutations. Idempotency binds actor, scope, action and canonical input. Check authentication, stored operation visibility, then replay before mutable-state preconditions for an existing identical intent. Cursor binds filter and scope. Typed capability bindings in the phase docs are logical actions. Route publication depends on DEC-012.

## Acceptance and test design

**REQ-P23-01 / AC-P23-01**. Same idempotency key and canonical intent return same operation, changed intent returns 409. Pagination cursor cannot switch tenant or filter. Invalid signature causes no enqueue.

**TC-P23-01 · Procedure**. Repeat identical request, change payload under same key, alter tenant cursor, and send forged webhook.

**Expected**. One operation and one accepted event for the valid intent. Changed payload, cursor and forged requests rejected.

**TC-P23-02 · Companion test**. Read two pages using valid cursor in same scope and submit one valid signed callback.

**Expected**. Pages have stable scope with no duplicate row; callback is recorded once.
