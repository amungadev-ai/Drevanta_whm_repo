# Phase 09 — Networking, firewall and DNS

**Owner role**  Network lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Separate read-only interface and listener inventories from mutations. Host network, firewall and SSH changes use scoped plans, pre-change snapshots and watchdog rollback that survives UI loss. Verify approved management reachability from an independent vantage before committing. Domain ownership and routing are independent checks. Normalize DNS names consistently and allow external DNS guidance without requiring authoritative DNS hosting.

## Contract and operational behavior

Firewall change plan binds original rules digest, desired rules, protected port set, expiry and rollback timer. Persist watchdog locally before change. Confirmation is from fresh authorized access, bound to change ID, before expiration. Track management addresses and record family-specific results. Custom hostnames need canonical ownership, authoritative and configured resolver evidence as applicable, and admission before TLS. Define DNS record/value guidance, TTL, verification timestamps and bounded propagation retry behavior in DEC-014.

## Acceptance and test design

**REQ-P09-01 / AC-P09-01**. A change that prevents a fresh authenticated management connection reverts to the saved rules when the confirmation deadline expires. DNS mismatch remains pending or failed with observed answers.

**TC-P09-01 · Procedure**. Remove the only management rule on a disposable VPS with rollback armed. Return a stale DNS record from a resolver.

**Expected**. Independent reachability fails, prior rules return, and domain remains unverified with actionable details.

**TC-P09-02 · Companion test**. Apply a safe rule set and confirm from a fresh approved connection.

**Expected**. Desired digest remains active after timer expiry and evidence records family-specific probes.
