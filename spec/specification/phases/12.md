# Phase 12 — Website and application lifecycle

**Owner role**  Hosting engineering lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Use draft → provisioning → active → suspended → archived → deleting → deleted with separate failure and reconciliation status. Provision after tenant, quota, hostname and host checks. Record each owned file root, identity, service and domain binding. Reversible suspension preserves data. Archive and destructive delete apply retention and approval policy. Transfer locks affected resource and recomputes grants and quotas.

## Contract and operational behavior

Plan lists inputs (tenant, plan version, host, root, runtime profile, hostname and requested resources) and effect checklist. Provision records secrets as references. Persist postcondition per step and compensate only owned allocations. Display operation progress, last known state and retry or operator action. Transfer preserves historic audit, rotates credentials where required, invalidates stale grants, and updates quota ownership in the same commit as ownership. Deletion produces a tombstone until retention and cleanup evidence complete.

## Acceptance and test design

**REQ-P12-01 / AC-P12-01**. Partial provisioning changes are reconciled using ownership tags. A failed provision cannot make a site active or delete a resource created by a different operation.

**TC-P12-01 · Procedure**. Fail TLS setup after reserved hostname and file-root creation. Retry using same key, then transfer site and test an old grant.

**Expected**. One site and one root; no active state until health passes. Old access is revoked at transfer commit.

**TC-P12-02 · Companion test**. Provision a site, suspend it, then resume it and verify a known owned file.

**Expected**. Site serves only in active state and the file survives suspension.
