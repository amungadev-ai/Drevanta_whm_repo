# Phase 10 — Web server, HTTPS and certificate management

**Owner role**  Web infrastructure lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Generate vhost config from validated structured inputs. Reserve hostnames across tenants, test staged config, swap atomically and verify health after reload. Restore old config on failed activation. Track pending DNS, eligible, issuing, active, renewal due and degraded states. Validate certificate chain, hostname and private-key binding before activation. Use a last-known-good certificate until expiry and surface renewal failure.

## Contract and operational behavior

Domain record holds canonical hostname, tenant, target, DNS proof and current/desired TLS generation. Certificate record holds issuer, validity, SAN set and key reference. Select supported challenge method in DEC-014. Persist issuance attempts, throttle retries and report expiry independently of renewal outcome. Redirects activate only when destination HTTPS serves the expected host and do not create loops. Public certificate status can expose expiry and validity with redacted diagnostics.

## Acceptance and test design

**REQ-P10-01 / AC-P10-01**. Invalid syntax, conflicting hostname or invalid certificate cannot replace a working configuration. Serving state requires a successful HTTPS probe for the target hostname.

**TC-P10-01 · Procedure**. Submit colliding hostname, wrong SAN and config with invalid upstream. Inject reload failure after swap.

**Expected**. Previous route stays or is restored. Events identify failed validation/activation step without disclosing key material.

**TC-P10-02 · Companion test**. Bind one unique domain, issue test CA certificate and renew with updated validity.

**Expected**. Matching hostname serves, renewal records new generation, prior route stays operational.
