# Phase 18 — Roles, permissions and tenant isolation

**Owner role**  Authorization lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Evaluate actor, action, resource, owner scope, relationships, context and policy revision server-side on each access. Deny by default. Invitations and support access are expiring, scoped grants. Resolution follows explicit graph edges with no grant from persona switching. Recheck delayed work before dispatch, fence ownership changes and prevent stale actors from seeing jobs, artifacts and logs.

## Contract and operational behavior

Proposed access defaults: platform operator → installation host administration, with separate grants for customer payload; organization admin → organization memberships and allocations; customer/site owner → owned site and authorized delegation; developer → assigned project/environment actions; support → approved expiring subset. Host access and product workspace roles are separate. Scope never expands through UI switching. Gate queries, downloads, events and workers on current policy and scope. Revoke at source and advance authorization revision.

## Acceptance and test design

**REQ-P18-01 / AC-P18-01**. Foreign list/detail/job/artifact requests leak zero entries or identifiers. A revoked actor cannot execute queued work and a queued operation cannot cross a resource ownership generation.

**TC-P18-01 · Procedure**. Use another organization's resource ID and guessed job ID, then revoke a test member while their mutation remains queued.

**Expected**. Foreign requests give 404 and filtered lists. Revoked operation never reaches agent; access decision audited.

**TC-P18-02 · Companion test**. Use approved site grant to list, read and mutate allowed resource.

**Expected**. Only allowed object appears, scoped action succeeds and policy decision is correlated.
