# Phase 24 — Testing, release engineering and production readiness

**Owner role**  Release lead  
**Documentation status**  Drafted and structurally checked  
**Engineering status**  Proposed, with runtime evidence pending

## Purpose and scope

Version source, build, schemas and compatibility matrix. Separate documentation checks from runtime verdicts. Require evidence for unit, contract, integration, authorization, browser, disposable VPS, fault injection, upgrade, restore and benchmarks. Promote immutable artifacts through isolated staging, then use reviewed staged rollout and rollback criteria. Record exclusions and links to policy decisions.

## Contract and operational behavior

Gate evidence includes exact commit and artifact digest, environment image/tuple, test ID, timestamp, expected/actual, verdict and durable artifact. At minimum exercise all supported platform tuples, old/new schema compatibility, brownout and restore, and authorization boundaries. Release gate sequence is scope → build → environment → tests/security → recovery → operational readiness → authorization. Canary halt/rollback thresholds must come from approved targets and measured staging evidence.

## Acceptance and test design

**REQ-P24-01 / AC-P24-01**. Certification fails whenever one required test lacks exact environment/commit and pass evidence, a critical/high release blocker is open, or production authorization is absent.

**TC-P24-01 · Procedure**. Attempt certification with all but one mandatory row passed, with drifted artifact digest, and with a misbound approval.

**Expected**. Each attempt blocked with precise reason. Only internally consistent evidence qualifies for review.

**TC-P24-02 · Companion test**. Evaluate evidence set bound to effective release scope and authorized staging candidate.

**Expected**. All applicable gates report passed only for that exact candidate, ready for independent review.
